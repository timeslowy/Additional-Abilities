# 触发类型（trigger_type）

> 适用：Additional Abilities for DS `2.0.0` · Dragon Survival `≥ 2.0.68`
> 相关：`activation.trigger.trigger_type` —— **只有 `activation_type: dragonsurvival:passive` 才有 `trigger`**

被动技能靠 `trigger` 决定「**什么时候**执行」。`trigger_type` 与触发器自己的参数（如 `condition`）
**平级**写在 `trigger` 对象里：

```jsonc
"activation": {
  "activation_type": "dragonsurvival:passive",
  "trigger": {
    "trigger_type": "additional_abilities:xxx",
    /* ← 该触发器自己的字段也写在这一层 */
  }
}
```

> - 整个 `trigger` 可以省略 —— 默认是 DS 内置的 `dragonsurvival:constant`（常驻，每 tick 执行）。
> - **事件型被动不参与每 tick 更新**，只在触发条件成立的那一帧执行一次。
> - 本模组这一层是**二级分派**：`activation_type` 分派到 `passive`，其内部再按 `trigger_type` 分派。

---

## 本模组新增的触发器

| `trigger_type` | 一句话 | 同源的内置类型 |
|---|---|---|
| `additional_abilities:on_block_placed` | **放下**方块时触发 | `dragonsurvival:on_block_break`（**破坏**方块时触发） |
| `additional_abilities:on_item_consumed` | **消耗**物品时触发 | 原版进度准则 `minecraft:consume_item`（字段结构同构） |

---

## 一、`additional_abilities:on_block_placed` 放置方块

**一句话**：DS 内置 `dragonsurvival:on_block_break` 的**判定反向版** —— 结构与字段完全相同，
只是事件从「破坏方块」换成「放下方块」，因此**同样使用方块战利品上下文**。

### 字段

| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `condition` | 战利品条件 | ❌ | 无（恒为真） | 在**方块战利品上下文**中求值，见下 |

字段与 `dragonsurvival:on_block_break` 逐字相同。**把 `trigger_type` 换掉，就能把任意
「破坏方块时」的被动改成「放下方块时」。**

### 示例

```json
{
  "activation": {
    "activation_type": "dragonsurvival:passive",
    "trigger": {
      "trigger_type": "additional_abilities:on_block_placed",
      "condition": {
        "condition": "minecraft:location_check",
        "predicate": {
          "block": {
            "blocks": "#minecraft:dirt"
          }
        }
      }
    }
  }
}
```

### 什么时候触发

- 玩家**手持物品右键放下方块**时触发一次；
- 一次交互放下**多个**方块（床 / 门 / 高植被等）也只算**一次** —— 位置与方块状态取**第一个**方块
  （`snapshot[0]`）；
- **只有龙形态的玩家**才会触发（与 `on_block_break` 一致）；触发的是**放置者自己**的技能，
  不是周围所有人的；
- 每次触发执行一次 `ability.tick(玩家)`：动作只结算**一帧**。需要持续附着效果（属性修饰符、
  状态效果）请改用 `constant` 常驻被动。

### 覆盖范围（重点）

| 放置来源 | 是否触发 |
|---|---|
| 玩家右键放下方块 / 物品 | ✅ |
| 桶、瓶倒出流体 | ❌ |
| 发射器、潜影盒发射器 | ❌ |
| 落沙 / 落砾落地 | ❌ |
| 末影人搬方块 | ❌ |
| `/setblock`、`/fill` | ❌ |
| 结构方块、结构与世界生成 | ❌ |
| 树苗长树、植物生长 | ❌ |
| 流体蔓延（水流出新方块等） | ❌ |

原因：本触发器接的是 NeoForge 的 `BlockEvent.EntityPlaceEvent`。该事件只在
**玩家的 `ItemStack#useOn` 走完放置流程**时抛出，上表里的其它来源都不经过这条路径
（桶类物品连 BlockSnapshot 都不捕获，因此连事件都不会产生）。

> 所以它的定位是「**玩家放下方块**」，而不是「世界上任何位置出现了方块」。
> 后者需要另外挂 `FluidPlaceBlockEvent` 等各自的事件，本模组暂未覆盖。

### 上下文与谓词

`condition` 在**方块战利品上下文**里求值，可用参数：

| 参数 | 含义 |
|---|---|
| `this_entity` | **放置方块的龙玩家自己**（判断自身状态用 `"entity": "this"`） |
| `origin` | 方块中心坐标 |
| `block_state` | **放下的那个方块**（放置完成后的状态，含朝向 / 含水等属性） |
| `block_entity` | 该位置的方块实体（可选，无则不含此参数） |

> ⚠️ **`condition` 里写的是原版「战利品条件」（`minecraft:loot_condition_type` 注册表），
> 不是方块谓词类型** —— 这里最容易踩坑：
>
> - ✅ 按**标签**判方块：`minecraft:location_check` → `predicate.block.blocks: "#minecraft:dirt"`
>   （`blocks` 是 `HolderSet`，接受 `"#命名空间:标签"` 或方块 id 列表；
>   注意它读的是 `origin` 处的**实时方块**，而非上下文里的 `block_state`）
> - ✅ 按**单个方块**判：`minecraft:block_state_property` → `block: "minecraft:dirt"`
>   （读上下文里的 `block_state`；**只支持单个方块 id，不支持标签**，可另加 `properties`）
> - ❌ `{"condition": "minecraft:matching_block_tag", "tag": "..."}` —— `matching_block_tag`
>   属于 **`block_predicate_type`** 注册表（只能嵌在 `BlockPredicate` 里），当成 `condition` 写会报
>   `Unknown registry key in ResourceKey[…minecraft:loot_condition_type]`，
>   且**直接导致世界无法加载**。
> - 其余可直接用的原版条件：`minecraft:all_of` / `any_of` / `inverted` / `random_chance` /
>   `weather_check` / `time_check` / `value_check` / `reference` 等。

### 用法要点

- **它不取消任何东西。** 内置的 `on_block_break` 在技能改动过方块时会**取消**破坏事件；
  放置版**有意不复刻**这一行为 —— 放置事件是在方块**已经放下之后**才抛出的，取消等于「回滚放置
  并退还物品」，语义完全不同。所以它是纯粹的**观察**触发器。
- **不参与每 tick**：与所有事件型被动一样，只在放置的那一帧执行。
- **想限流就写 `cooldown`**。建筑时放置频率很高，每次放置都会遍历该玩家的全部技能做
  `instanceof` + 谓词判定（DS 侧尚未缓存），配 `cooldown` 是最直接的限流手段。
- **`trigger_point` 必须保持 `default`**：DS 对被动技能（含事件型）的硬性要求，
  写成别的值会在数据加载阶段抛 `IllegalStateException`。
- **侧边栏会多出一行** `■ Trigger: 放置方块时`（语言键 `trigger_type.additional_abilities.on_block_placed`）。

### 测试技能

| 技能 id | 配置 | 用途 |
|---|---|---|
| `additional_abilities:test_on_block_placed` | 本触发器 + `condition = #minecraft:dirt` | 放下泥土类方块（泥土 / 草方块 / 砂土 / 菌丝等）时自身发光 + 末地烛粒子；放石头一类不触发 |

未挂在任何龙种下，需要 `/dragon-ability add <目标> <技能>` 自行授予。

> 该测试技能同时也是「标签谓词」的抄写样板：去掉 `condition` 即为「放下任何方块都触发」。

## 二、`additional_abilities:on_item_consumed` 消耗物品

**一句话**：吃下或饮下**匹配的物品**时触发一次。字段结构**对齐原版进度准则
`minecraft:consume_item`**（同样是物品谓词 `ItemPredicate`），但驱动源换成了被动技能系统，
因此可以挂任意 `actions`。

### 字段

| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `item` | `ItemPredicate` | ❌ | 无（恒为真） | **物品谓词**，写法与原版完全一致，见下 |

`ItemPredicate` 的子字段：

| 子字段 | 类型 | 说明 |
|---|---|---|
| `items` | `HolderSet<Item>` | 物品 id 列表，或 `"#命名空间:标签"`（如 `"#minecraft:meat"`） |
| `count` | 整数范围 | 写裸数字 `5` 表示**恰好** 5 个；也可写 `{"min": 1, "max": 3}` |
| `components` | 数据组件谓词 | 按组件精确匹配，如 `{"minecraft:damage": 0}`、`{"minecraft:custom_name": "..."}` |
| `predicates` | `ItemSubPredicate` | 按子谓词匹配（`minecraft:damage` / `minecraft:enchantments` / `minecraft:potion_contents` 等） |

### 示例

```json
{
  "activation": {
    "activation_type": "dragonsurvival:passive",
    "cooldown": 100.0,
    "trigger": {
      "trigger_type": "additional_abilities:on_item_consumed",
      "item": { "items": "#minecraft:meat" }
    }
  }
}
```

### 什么时候触发

- 玩家把物品**用到底（读条结束）**时触发一次，且**只有龙形态的玩家**会触发；
- 触发的是**消耗者自己**的技能，不是周围玩家的；
- 每次触发执行一次 `ability.tick(玩家)`：动作只结算**一帧**。需要持续附着效果（属性修饰符、
  状态效果）请改用 `constant` 常驻被动。

### 覆盖范围（重点：与原版 `consume_item` 的差异）

原版 `minecraft:consume_item` 准则**没有统一钩子** —— 1.21.1 里它由 **5 处硬编码调用**驱动：
`Player#eat`（一切可食用物品）、`PotionItem`、`HoneyBottleItem`、`MilkBucketItem`、
`OminousBottleItem`。本触发器改接 NeoForge 的 `LivingEntityUseItemEvent.Finish`
—— 上述 5 处**全都位于 `LivingEntity#completeUsingItem` 内部**，因此能被一次性覆盖，
且**不需要任何 Mixin**。

| 场景 | 原版 `consume_item` | 本触发器 |
|---|---|---|
| 食物（面包 / 金苹果 / 熟肉 / 迷之炖菜 / 紫颂果…） | ✅ | ✅ |
| 药水 | ✅ | ✅ |
| 蜂蜜瓶 | ✅ | ✅ |
| 奶桶 | ✅ | ✅ |
| 不祥之瓶 | ✅ | ✅ |
| 山羊角（读条 140 tick 结束） | ❌ | ⚠️ 会触发 |
| 望远镱（读条 1200 tick 结束） | ❌ | ⚠️ 会触发 |
| 刷子（读条 200 tick） | ❌ | ⚠️ 可能触发 |
| 蛋糕 / 蜡烛蛋糕（方块交互，走 `FoodData#eat`） | ❌ | ❌ |
| 其它模组直接调用 `Player#eat` | ✅ | ❌ |

多出来的一律是「**非消耗品**」，写正常 `item` 谓词即可天然过滤（你总不会给山羊角写消耗技能）；
漏掉的只影响绕过 `completeUsingItem` 的第三方模组。要逐字一致只能对上述 5 处做 Mixin，
本模组有意不采用。

### 两个陷阱

1. **`count` 看的是消耗前的数量。** 原版的触发点早于扣减，本触发器拿到的也是「使用前的副本」，
   所以 `"count": 1` 对一叠 64 个面包**不匹配**（此行为与原版一致）。
2. **匹配的是消耗前的物品。** 蜂蜜瓶 → 玻璃瓶、奶桶 → 空桶这类「消耗后替换」不影响匹配结果。

### 用法要点

- **想限流就写 `cooldown`**：与所有事件型被动一样，它只在触发的那一帧执行。
- **`trigger_point` 必须保持 `default`**：DS 对被动技能（含事件型）的硬性要求。
- **不做同 tick 去重 / 防环**（与 `on_block_break`、`on_block_placed` 一致）；
  若某技能的效果会再引发一次消耗，请自行加 `cooldown`。
- **侧边栏会多出一行** `■ Trigger: 消耗物品时`
  （语言键 `trigger_type.additional_abilities.on_item_consumed`）。

### 测试技能

| 技能 id | 配置 | 用途 |
|---|---|---|
| `additional_abilities:test_on_item_consumed` | 本触发器 + `item.items = "#minecraft:meat"` | 吃下生/熟牛、鸡、羊、猪、兔肉或腐肉时自身发光 + 末地烛粒子；吃面包一类非肉类不触发 |

未挂在任何龙种下，需要 `/dragon-ability add <目标> <技能>` 自行授予。

> 该测试技能同时也是「物品谓词」的抄写样板：把 `item` 整个删掉即为「消耗任何物品都触发」。
