# 激活类型（activation_type）

> 适用：Additional Abilities for DS `2.0.0` · Dragon Survival `≥ 2.0.68`
> 相关：`activation.activation_type`
> 另见：[08-触发类型.md](08-触发类型.md) —— 被动技能（`activation_type: dragonsurvival:passive`）
> 内部还有一层 `trigger.trigger_type`，决定这个被动**什么时候**执行

---

## `additional_abilities:charged` 蓄力档位

**一句话**：按住技能键蓄力，**松手时按蓄到的档位释放**；蓄得越久越强。

行为上等价于 `dragonsurvival:simple` 的「按住读条」，但读条过程被理解为**蓄力**：
按住期间逐档提升，松手那一刻按已达到的档位执行一次技能。

### 字段

| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `charged_duration_per_level` | 等级数值 | ✅ | — | 各档位所需的蓄力时长（tick）。第 L 档 = 该函数在 L 处的取值 |
| `cast_time` | 等级数值 | ✅ | — | 总蓄力上限（tick）。**必填且必须为正**，为 0 或负数时数据包加载直接报错 |
| `can_charge_exceed_cast_time` | 布尔 | ❌ | `false` | 能否按满后继续按住不释放，见下 |
| `cooldown` | 等级数值 | ❌ | `0` | 冷却时长，**按最终档位结算** |
| `initial_mana_cost` | 等级数值 | ❌ | `0` | 初始魔力消耗，**按最终档位结算** |
| `notification` | 对象 | ❌ | 同 DS | 魔力不足 / 被禁用的提示文案 |
| `can_move_while_casting` | 布尔 | ❌ | `true` | 蓄力期间能否移动 |
| `sound` | 对象 | ❌ | — | 同 `simple`，但**不支持 `looping`**（写了会报错） |
| `animations` | 对象 | ❌ | — | 同上，**不支持 `looping`**（写了会报错） |

> `cast_time` 在 `dragonsurvival:simple` 里是可选的，本类型把它改成**必填且必须为正** ——
> 因为它就是「总蓄力上限」，缺失或为 0 会让蓄力过程失去意义，所以在数据包加载期就报错，
> 而不是留到运行时表现异常。

### 示例

```json
"activation": {
  "activation_type": "additional_abilities:charged",
  "can_move_while_casting": false,
  "cast_time": 50.0,
  "charged_duration_per_level": {
    "type": "minecraft:linear",
    "base": 10.0,
    "per_level_above_first": 10.0
  },
  "cooldown": 60.0,
  "initial_mana_cost": 1.0,
  "sound": {
    "charging": "block.conduit.activate",
    "end": "block.enchantment_table.use"
  }
}
```

上面这份配置的含义：档位 1~5 分别需要蓄力 10 / 20 / 30 / 40 / 50 刻；总上限 50 刻
（默认模式下实际可用到 49 刻，见下方换算），所以 5 档全部可达。

## `additional_abilities:optional_charged` 可选性蓄力档位

**一句话**：`charged` 的改版 —— 蓄力期间用**鼠标滚轮**自由挑选要释放的档位，甚至可以选择「取消，不释放」。

字段与 `charged` **完全一致**（同上表），只有一处默认值不同，另加一套滚轮交互。

### 与 `charged` 的差异

| 项 | `charged` | `optional_charged` |
|---|---|---|
| `can_charge_exceed_cast_time` 默认 | `false` | **`true`** |
| 松手时用的档位 | 已蓄到的档位 | 玩家用滚轮**选定**的档位 |
| 可否取消 | 只能在未达第 1 档时松手取消 | **任意时刻都可以**（把档位选到 `0`） |

> **为什么默认改成 `true`**：选档需要「按满后不释放」的时间窗口。若保持 `false`，DS 会在
> `currentTick == cast_time` 当刻以玩家最高档自动打出去，玩家根本来不及挑。
> 该字段仍可显式写成 `false`，但那样选档只在 `[0, cast_time - 1]` 这段窗口内有效。

### 滚轮交互

按住技能键蓄力期间：

| 操作 | 效果 |
|---|---|
| 上滚 | 释放档位 +1 |
| 下滚 | 释放档位 -1 |
| 下滚到 `0` | 选定为**取消**：松手什么都不放 |

**可选范围恒为 `[0, 当前已蓄到的档位]`** —— 选不到还没蓄到的档位。
未达第 1 档时没有任何可选项，因此此时滚轮不接管，照常切换快捷栏物品。

**默认自动跟随**：不滚动时释放档位等于已蓄档位，表现与 `charged` 完全一致。
一旦滚动即转为**手动指定**；把档位滚回「已蓄到档位」即恢复自动跟随。

**手动指定不会锁死蓄力**：已蓄档位仍继续上升（例如已蓄到 5、选定 3 后继续按住，已蓄仍是 5），
可随时再上滚回 4、5。

> **注意**：蓄力期间滚轮被技能占用，**不会切换快捷栏物品**（有意为之）。

### 取消的代价

选定 `0` 后松手 = 取消施法：**不执行任何动作、不扣初始魔力、不进冷却**，并立即清理循环音效与技能动画。

> 这里刻意不走 DS 原生的停手路径：`DragonAbilityInstance#isApplyingEffects()` 的判定是
> `currentTick >= cast_time`，而开启 `can_charge_exceed_cast_time` 后「按过上限仍在蓄力」这一段
> 会让它**提前为 true**，DS 会据此误判为「效果已生效」而施加冷却、播放结束音效与结束动画。
> 因此取消由本模组显式以「不进冷却」的方式收尾，并自行广播停止音效与停止动画。

### 数值平衡提示

`cooldown` 与 `initial_mana_cost` 同样按**最终释放的档位**结算，所以低档释放天然更便宜 —— 这是设计意图。
但若把这两项配成随档位**递减**，会出现「刷低档反而更划算」的收益倒挂，建议保持随档位非递减。

## 档位换算

```
第 L 档所需蓄力刻数 = min( charged_duration_per_level(L), 蓄力上限 )

蓄力上限 = cast_time          当 can_charge_exceed_cast_time = true
         = cast_time - 1      当 can_charge_exceed_cast_time = false（默认）
```

**默认模式为什么上限要减 1**：DS 在 `currentTick == cast_time` 的**当刻**就会完成释放并立刻停手，
那一帧玩家根本看不到。若把上限压在 `cast_time`，最高档的落点就落在这一帧上 ——
满档的数字与提示音永远不会出现，而且「最后一刻松手」会比「按满自动释放」还低一档，自相矛盾。
前移 1 刻就消除了这个错位。

**开启 `can_charge_exceed_cast_time` 后**：蓄力按满可以继续按住不释放，`currentTick` 会越过 `cast_time`，
上限即 `cast_time` 本身，满档可以一直保持并显示在 HUD 上，只有松手才释放。

## 行为一览

| 情况 | 结果 |
|---|---|
| 蓄力 < 第 1 档所需时长就松手 | **取消施法**：无冷却、无效果、不扣蓝（与 DS 原生「提前松手」路径一致） |
| 蓄力 ≥ 第 1 档，松手 | 按当前档位释放一次：扣初始魔力 → 执行动作 → 按档位结算冷却 / 结束音效 / 结束动画 |
| 蓄到 `cast_time` | 由 DS 原生的「读条完成」自动释放，档位 = 玩家自身升级等级（满档） |
| 开启 `can_charge_exceed_cast_time` | 按满后可以一直按住不放，档位停在自身最高档；**只有松手才释放，不会自动释放** |
| `optional_charged`：选定档位后松手 | 按**选定档位**释放（`charged` 下这一格永远是「已蓄到的档位」） |
| `optional_charged`：选定 `0` 后松手 | **取消施法**：不执行动作、不扣初始魔力、**不进冷却**，并清理循环音效与技能动画 |

## 档位影响了什么（重点）

**凡是按等级求值的字段，全部改按「档位」而不是玩家升级等级结算。** 具体包括：

- 技能内**全部动作参数** —— 伤害、弹射物数量 / 速度 / 散布、方块效果参数、概率判定、时长等；
- **`cooldown`** —— 收尾走 DS 原生 `release`，其内部读 `getCooldown(level)`，所以冷却长度随档位变化；
- **`initial_mana_cost`** —— 初始魔力消耗按档位算；
- **`cast_time`** —— 一并作为动作 `trigger_rate` 的取模基准。

**不受档位影响**的只有档位换算本身（`charged_duration_per_level` 逐级求值得到各档阈值）。

### 两处边界，配置时容易踩

1. **档位不会超过玩家的升级等级。** 只升到 3 级的玩家，蓄满也只是按 3 级结算上面全部数值。
2. **起手校验用的是真实等级。** 按下技能键那一刻，DS 用玩家**真实等级**对应的 `initial_mana_cost`
   校验法力。所以「想放低档省蓝」是不成立的 —— 要放低档也得先付得起满档的起手门槛。
3. **延迟型效果读不到档位。** 生成实体后由该实体在后续游戏刻才去读技能等级的效果（例如某些弹射物派生逻辑），
   读到的是玩家真实等级。**同一 tick 内立即结算**的效果（伤害、弹射物生成、方块效果、概率判定）不受影响。

## HUD 与查询

### 屏幕提示

蓄力条右侧会实时显示**当前档位数字**（**位置可配置**，见下）：

| 颜色 | 含义 |
|---|---|
| 灰 | 还没到第 1 档（此时松手 = 取消） |
| 白 | 蓄力中 |
| 金 | 已达玩家自身等级上限（满档） |

每跨升一档播一次提示音，音高随档位递增（**音效与曲线都可配置，见下方「提示音」**）。**显示的数字就是松手时实际会用的档位。**

`optional_charged` 下读数区会按状态变形（第二行的进度条与百分比含义不变）：

| 状态 | 显示 | 颜色 |
|---|---|---|
| 自动跟随（未滚动） | 单个数字 = 已达档位 | 白 / 满档金，同 `charged` |
| 手动选档 | `选定/已达`，例如 `3/5` | 选定值为**青蓝**，`/已达` 为灰 |
| 手选定为取消 | `0/已达`，例如 `0/5` | **红** |

滚轮每真正改变一次档位播一声点击音（音高随档位递增；选定 `0` 时用低音加以区分）。两者共用同一个开关与音量，见下方「提示音」。

### 屏幕位置（客户端配置）

读数区默认贴在蓄力条**右侧**、与蓄力条垂直居中。位置可以在
`config/additional_abilities-client.toml` 里改，也可以直接在游戏内
**「模组 → Additional Abilities for DS → 配置」**里改 —— 两种方式都**即时生效**，不用重启、也不用重进世界。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `charged_indicator.anchor` | `CAST_BAR_RIGHT` | 读数区贴在蓄力条的哪一侧（见下表） |
| `charged_indicator.offset_x` | `0` | 在所选方位之上再横向平移的像素数（向右为正） |
| `charged_indicator.offset_y` | `0` | 在所选方位之上再纵向平移的像素数（向下为正） |

四个方位（都跟随蓄力条的位置 —— 你在 DS 里挪动蓄力条时，读数区会跟着一起走）：

| `anchor` 取值 | 方位 |
|---|---|
| `CAST_BAR_RIGHT` | 蓄力条**右侧**，与蓄力条垂直居中（默认，即旧版行为） |
| `CAST_BAR_LEFT` | 蓄力条**左侧**，与蓄力条垂直居中 |
| `CAST_BAR_ABOVE` | 蓄力条**上方**，与蓄力条水平对齐 |
| `CAST_BAR_BELOW` | 蓄力条**下方**，与蓄力条水平对齐 |

四个方位与蓄力条之间都留 6 像素间距。

- 只给围绕蓄力条的四个方位，是刻意的：施法时视线本来就落在蓄力条上，读数区贴着蓄力条才不用移开视线；
  「屏幕四角 / 屏幕居中」那类预设看着自由，实战里反而没人会用。需要再错开一点就用偏移量，上限 ±4000 像素。
- 坐标单位是 **GUI 缩放后的像素**，与游戏界面同一套量纲 —— 换 GUI 缩放档位时读数区的绝对位置会跟着变，
  但方位语义不变。
- 贴左 / 贴上 / 贴下都会先扣掉读数区自身的宽高，所以是「**整块读数区**」贴边，
  不会出现半块露在屏幕外的情况。
- 这项配置**纯客户端**：不参与任何服务端判定，也不会随联机同步发给其他玩家。
- 游戏内配置界面里方位是一个下拉框（显示中文名），**不必手写**；手写时请用大写的枚举名，例如 `CAST_BAR_LEFT`。

### 提示音（客户端配置）

两种提示音都只在本机播放（属于"给自己听的档位提示"，不会发给其他玩家），并共用一个开关与一条音量倍率：

| 配置项 | 默认 | 说明 |
|---|---|---|
| `charged_indicator.play_sound` | `true` | 是否播放提示音。**档位提升音**（每升一档一声）与**滚轮选档音**（每次真正改变档位一声）一起开关 |
| `charged_indicator.sound_volume` | `1.0` | 总倍率（`0.0` ~ `1.0`），叠在两种音各自的**基准音量**之上（档位提升音 `0.7`、选档音 `0.6`） |
| `charged_indicator.level_up_sound` | `NOTE_PLING` | 档位提升音用哪个音效。**8 个固定预设**（下拉框选择）；默认即旧版的音符盒「叮」 |
| `charged_indicator.level_up_sound_pitch` | `0.9` | 第 1 档的起始音高（`0.5` ~ `2.0`；`1.0` 为音效的原始音高） |
| `charged_indicator.level_up_sound_pitch_per_level` | `0.12` | 每升一档增加多少音高（`0.0` ~ `1.0`；设 `0` 则各档同高） |
| `charged_indicator.level_up_sound_max_pitch` | `2.0` | 音高封顶（`0.5` ~ `2.0`） |

- 两种音的基准音量不同是**刻意的**（选档音更短、更轻），总倍率不会把两者拉平；默认 `1.0` 即与旧版响度一致。
- 关掉开关只影响本模组这两个提示音：**龙之生存自己的**蓄力音（`sound.charging`）与起始 / 结束音照常播放。
- 音量项没有"随开关联动灰化"的能力（NeoForge 21.1 的配置界面尚不支持），所以开关关掉时它仍可编辑，只是不生效。
- **音效只有 8 个预设是配置系统的硬限制**：`ModConfigSpec` 只支持基本类型与枚举，没有「注册表对象」类型；
  而原版单是音效就有 **1486** 个，下拉框也放不下。想要「任意已注册音效」需要自建带搜索的选择界面（目前没有）。
- **音高曲线**按 `min(起始音高 + 每档增量 × 档位, 音高上限)` 求值，**只作用于档位提升音**
  （滚轮选档音的音高固定不受影响）。游戏的声音引擎会把音高钳在 `[0.5, 2.0]`，所以上限给不出更高；
  短促的打击乐类音效升调悦耳，长音 / 环境音会明显失真 —— 换音效后建议顺带调一下曲线。

- 同一个音效若对应**多个音频变体**（原版 `sounds.json` 允许一个 id 映射多个文件，播放时随机挑一个），
  本模组的档位提升音**已锁死为固定变体**，所以同一档位的提示音每次完全一致（滚轮选档音未做此处理）。

> **行为变更**：按 `F1` 隐藏 HUD **不再**静音档位提示音。
> 旧版把"是否跨升一档"的判断写在 HUD 图层的渲染回调里，隐藏 HUD 会连带跳过这段判断，于是"隐藏画面"顺带把声音也静音了；
> 现在提示音由**客户端刻**驱动（每刻一次，与帧率无关），与 HUD 的可见性完全无关。

### 查询指令

```
/dragon-ability query <目标> <技能> current_charged_level
/dragon-ability query <目标> <技能> current_selected_level
```

`current_charged_level`：

- 正在蓄力 → 返回**当前蓄力对应的档位**；
- 没在蓄力 → 返回**最近一次实际释放**所用的档位（取消施法不写入）；
- 技能不是蓄力类型 → 返回 `0`。

`current_selected_level`（`optional_charged` 专用）—— 回答的始终是「**此刻松手会放几档**」：

- 手动选定过 → 返回**选定的释放档位**；`0` 表示已选定为**取消**；
- 处于**自动跟随**（没滚动过，或滚回了已蓄档位）→ 返回**已蓄到的档位**（这正是松手时实际会用的档位）；
- 未在蓄力、或蓄力还没到第 1 档 → 返回 `-1`（未指定）；
- 技能不是蓄力类型 → 返回 `-1`。

> 这里刻意**不**把"自动 / 手动"的内部状态透出去：一旦玩家滚回顶端，客户端就恢复自动跟随，
> 此时明明能算出具体档位，报告"未指定"（`-1`）只会误导调试。
> 也不存在"手动选到恰好等于已蓄档位"这种需要与自动跟随区分的状态 —— 两者效果完全等同。

## 技能信息面板（激活类型）

按 `Shift` 展开的「信息」侧栏，**首行**会显示该技能的激活类型：

| 激活类型 | 面板显示 |
|---|---|
| `dragonsurvival:passive` | 被动 |
| `dragonsurvival:simple` | 主动 |
| `dragonsurvival:channeled` | 引导 |
| `additional_abilities:charged` | 蓄力 |
| `additional_abilities:optional_charged` | 可选性蓄力 |

- 这一行是为了**区分 `charged` 与 `optional_charged`** 而加的：在龙生眼里两者都是
  `dragonsurvival:simple`（面板顶部一律写「主动能力」），行为却完全不同；而龙生本体
  **从不显示**激活类型本身 —— 它只给被动技能显示「触发条件」。
- 类型名由激活类型**自己的注册表 ID** 反查（译名键 `activation_type.<命名空间>.<路径>`），
  因此**其他模组注册的激活类型也会自动显示**，本模组不必跟着上游增删而改代码。
- 没有对应译名时退回显示**原始 ID**（如 `some_mod:my_type`），不会把机器键名画到界面上。
- 这一行**纯客户端**渲染，不参与任何服务端判定，也不会进入技能描述文本。

## 测试技能

| 技能 id | 配置 | 用途 |
|---|---|---|
| `additional_abilities:test_charged` | `cast_time: 50`、`can_charge_exceed_cast_time` 关闭 | 默认模式：按满自动释放，5 档可达 |
| `additional_abilities:test_charged_hold` | `cast_time: 60`、`can_charge_exceed_cast_time: true` | 开启超上限蓄力：按满后可一直按住 |
| `additional_abilities:test_optional_charged` | `cast_time: 60`、类型为 `optional_charged` | 滚轮选档：上滚 / 下滚挑档位，选到 `0` 则取消 |

两者都未挂在任何龙种下，需要 `/dragon-ability add <目标> <技能>` 自行授予。
